# Settings

This file loads when you work in `Macterm/Settings/`. The root `AGENTS.md` has the build, the architecture and the conventions.

The rule for the Settings window (`PinnedSidebar`, `DividerShield`) is in `Macterm/Views/AGENTS.md`, under "Windows and sidebars, AppKit reach-throughs".

- `Macterm/Settings/`
  - `SettingsView`: the panes and `PinnedSidebar`. The soft scroll-edge band of the titlebar darkens a selected first row. AppKit has no switch for the band, and a top margin does not clear it. Do not put a `.searchable` field in the sidebar to clear it: it blanks the icons of the unselected rows for about 100 ms at each open. Keymaps is one grouped block. Passthrough Programs is above it. The search is at its top. There is no row of column headers. Each `AppCommand.Category` is a header row that folds its indented rows (`groupHeader`, the chevron after the title), and the palettes of extensions are in a last Extensions group. The header is a row and not a `DisclosureGroup`, because in a grouped form a disclosure group draws no separators between its rows and does not indent them. A search folds in its own set, which each change of the query clears, so its matches always show. Each row has one menu for Global and Pass to TUI (`keymapRow`). A glyph after the title shows each flag that is on. The menu is an AppKit pull-down (`KeymapRowMenu`), because on macOS 26 and later a SwiftUI `Menu` drops its checkmark column while no item is checked. A bare Delete while a row records clears its keybind (`HotkeyCaptureView`). The clear badge of a mapped keybind (`KeybindButton`) clears it too. The badge shows while the pointer is on the keybind or while the row records.
  - `ProjectsSettings`, `WidgetsSettings`.
  - `ExtensionsSettings` (Settings → Extensions).
    - It is one grid of `ExtensionGalleryItem` cards that you can search by name. It has the installed extensions and the extensions of `PaletteRegistry` that are not installed yet. Each card shows the own name and description of the extension.
    - **Each card shows the screenshots of its extension** (`ScreenshotPager`): one page at a time in a paging `ScrollView`, with arrows and dots on the screenshot. `MactermExtension.screenshots(in:readme:)` sets the order: the README order, then by name, at most 6. A click opens `ScreenshotSheet`: the same pager at full size, at the screenshot that was clicked, where the Left and Right Arrow keys press the arrows. The pointer over a screenshot of a card is `.zoomIn` (macOS 15 and later). A card without screenshots shows the icon in the same space.
      - An installed card reads its files on disk. Any other card reads the repository's files. `ExtensionScreenshotLoader` (`PaletteRegistry.screenshots`) reads a screenshot only when a card shows it. It keeps the bytes and each decoded size for the run, keyed by blob SHA, and it does not keep a failed read.
      - The arrows do not wait for a hover. An AppKit tracking area (`RowHoverTracker`) does not follow content that a SwiftUI `ScrollView` moves. After a scroll, a hover showed the arrows of another card, and a click on a hidden arrow opened the sheet.
    - Each card has one button. **Install** installs at once, with no sheet. A book button next to it opens the folder of the extension on GitHub (`PaletteRegistry.folderURL`). **Installed** asks to uninstall the extension, and **Uninstall** moves it to the Trash (`CustomPaletteStore.uninstall`). The prompt names each feature of the extension (`InstalledExtension.features`, for now one "<name> palette" for each palette), so a later capability is in the message without a change to the prompt. An installed card also has an Update button (a glyph, `.borderedProminent`) when `ExtensionGalleryItem.update` offers one. See the updates bullet under `PaletteRegistry` in `Macterm/Palette/AGENTS.md`.
    - Installed extensions come first, and each group is in order of name or of search rank. A menu next to the search field filters the grid to **All**, **Installed** or **Not Installed** (`ExtensionGalleryItem.Filter`).
    - The built-in screens are not extensions, and they have no card. There is no switch for on and off. To remove an extension, uninstall it.
  - `PasswordsSettings`.
  - `IntelligenceSettings` (Settings → Intelligence, macOS 26 and later): a header block in the shape of a System Settings pane's (the features need Apple Intelligence, nothing leaves the Mac, a link to the docs), the switch of Project Insights (disabled without Apple Intelligence), and the status of Apple's on-device model. The header block says those facts one time: the sections below do not repeat them.
